## 1. 系统定位与使用角色

TMS 面向 POS 终端交付后的集中管理，核心业务包括设备激活与初始化、OTA 升级、RKI 远程密钥分发和设备模式控制，并提供客户、机构、账户权限、产品型号、设备流转、证书及日志管理。

| 默认后台角色 | 主要职责 |
| --- | --- |
| 平台管理员 | 管理客户、产品型号、平台库存和设备出库；维护 Kernel、APP、参数文件及对应 OTA 任务、设备模式任务、激活授权、CA 与平台服务证书等平台资源 |
| 客户管理员 | 管理本客户及下级机构设备、成员与角色；维护授权范围内的 APP、参数包及任务；向指定人员分配 RKI 权限 |
| 机构管理员 | 管理本机构授权范围内的设备、分组和任务；查看上级任务在本机构范围内的执行情况 |
后台默认角色保留平台管理员、客户管理员、机构管理员三类。运维、密钥操作及只读查看需求通过自定义角色配置，不增加独立的首页身份。实际功能由菜单权限、操作权限和数据范围共同决定。

- 密钥操作员：按客户需要配置，授权导入支付密钥、创建和维护RKI任务及查询执行记录。
- 只读账户：可自定义“设备查看员”等角色，仅授予所需模块的查看权限。沿用客户或机构工作台，隐藏创建、转移、停止等维护操作，不授予管理员权限；导出能力另行授权。
- 激活人员：使用激活工具完成激活，受账户、设备范围、有效期和次数额度控制；不属于默认管理后台身份。工厂人员在整机组装阶段对抽检设备执行工厂激活；客户授权人员对出库到货的设备执行出厂激活；售后人员对防拆触发设备执行防拆激活。

## 2. 首页与公共功能

### 2.1 首页工作台

| 使用角色 | 核心统计 | 页面内容 | 快捷入口 |
| --- | --- | --- | --- |
| 平台管理员 | 设备总数、库存设备、出库设备、已激活设备 | 激活趋势、设备型号分布、客户设备分布、最近出入库 | 设备出库、设备入库 |
| 客户管理员 | 设备总数、已激活设备、触发防拆设备、执行中任务 | 设备活跃趋势、设备型号分布、任务列表、运维提醒 | 创建OTA任务、创建RKI任务 |
| 机构管理员 | 设备总数、已激活设备、触发防拆设备、执行中任务 | 授权范围内的设备活跃趋势、型号分布、任务列表、运维提醒 | 创建OTA任务、设备转移 |

客户与机构共用工作台，根据模块权限和数据范围展示内容；只读账户复用该页面，隐藏维护入口。原型账户切换保留平台管理员、客户管理员、机构管理员三个入口。

布局：页头显示工作台、刷新和机构；蓝色渐变横幅保留日期、用户问候及最多两个常用入口。第一行显示四项核心统计，第二行左侧为设备活跃趋势、右侧为设备型号分布，第三行左侧为任务列表、右侧为运维提醒。白色卡片搭配蓝、绿、红、紫色指标标识。平台首页第二行左侧为激活趋势、右侧为设备型号分布，第三行左侧为客户设备分布、右侧为最近出入库；不展示任务列表与运维提醒。统计卡片只显示名称、统计时段与数值。窄屏自动换列，按钮文字不拆行。

不展示宣传文案、设计说明和统计实现细节。移除“执行中任务进度”图、“待执行设备／台次”和独立OTA／RKI任务统计卡；任务进度在具体任务行内查看，失败台次仅出现在运维提醒中。

设备统计口径：

- 设备总数、已激活、触发防拆、活跃趋势和型号分布均按当前账户可查看、未报废的设备统计，工作台与设备列表的同名统计使用同一口径、数值一致；未授权设备模块时隐藏对应统计与图表。
- 已激活设备按设备当前激活状态计数，每台只计一次；不累计激活记录，不把曾激活后已失效的设备算作当前已激活。激活成功由后端更新设备当前状态。已激活不代表密钥齐备、处于产品模式或当前可正常交易。
- 触发防拆设备：防拆状态为“已触发”的设备，每台只计一次。设备上报防拆触发时，平台将防拆状态置为已触发，并记录触发时间与触发原因；该设备完成防拆激活后恢复为正常。远程模式任务不改变防拆状态。
- 点击触发防拆设备卡片进入明细，展示SN、型号、所属机构、触发原因、触发时间，按触发时间倒序，分页展示。
- 有效通信包括身份校验通过的任务查询、设备状态上报或执行结果上报。管理后台查询、失败鉴权和仅建立TCP连接不更新最近有效通信时间 `last_seen_at`。以服务端接收时间为准，不使用设备自报时钟。
- 设备活跃趋势：按 UTC 日期统计，当日至少有一次有效通信的设备计为当日活跃，同一设备当日只计一次。活跃不表示在线状态。
- 设备活跃趋势以柱状图展示近7天（默认）或近30天的每日活跃设备数，最后一根为今日（截至当前），以斜纹区分；虚线为当前设备总数，图例显示设备总数。图例位于三项数值右侧，窄屏时换行显示。纵轴从0开始；近30天每5天标注一个日期，并标注今日。
- 图上方显示日均活跃、日均活跃率与单日最低三项，均不含今日：日均活跃为所选范围内各历史日期活跃设备数的平均值；日均活跃率为日均活跃除以当前设备总数，保留1位小数；单日最低显示历史日期中活跃设备数最少的一天及其日期，并列时取较早日期。数值100台以下保留1位小数，100台及以上取整。
- 悬停柱形显示日期、活跃设备数及占当日设备总数的比例（历史日期取当日汇总的设备总数，今日取当前设备总数）；点击柱形进入当日活跃设备明细，展示SN、型号、所属机构、激活状态、最近有效通信时间，分页展示。
- 历史日期的活跃设备按当日设备归属机构统计；设备转移后，历史日期仍计入原机构，转移当日起计入新机构。设备报废后不计入报废之后的日期。
- 型号分布展示型号、数量与占比，中心显示设备总数。按数量倒序，不超过6类全部展示，超过6类展示前5类及“其他型号”；缺失型号归入“未登记型号”。占比保留1位小数。
- 点击型号查看该类设备，其他型号展开剩余型号设备；单型号显示100.0%，空数据显示0和“暂无设备”。报废排除与权限范围同顶部设备总数。

任务、提醒与平台统计：

- 执行中任务卡合并当前有查看权限的OTA／RKI等任务，按任务去重，排除草稿、已完成、已停止；保留上级任务在当前机构设备上的可见性，不单独统计任务来源数量。
- 任务列表优先执行中，同优先级按创建时间倒序，最多6条；具体任务行展示本数据范围内的设备进度。跨机构任务保持只读；类型页签按模块权限展示。
- 运维提醒只展示数量大于零的项目：客户／机构显示任务执行失败、未激活设备、锁定设备、超过7天未通信设备，并按权限显示已到期与30天内到期证书。没有项目时显示“暂无运维提醒”。未激活和锁定属于提醒状态，不直接判定为故障或防拆。超过7天未通信设备：`last_seen_at` 早于统计时点7天以上的设备，无有效通信记录的设备不计入；明细按最近有效通信时间升序。
- 运维提醒不单独建表、不生成提醒记录，每次加载时按上述口径从设备、任务执行项、激活记录、证书等业务表实时计数，数值与业务数据始终一致，业务数据变化后提醒随之消失，无需已读、关闭或清理。每项点击进入对应的筛选明细。各计数使用已有索引字段查询，随首页短缓存一起失效。顶部消息通知复用相同口径。
- 执行失败仅统计执行中任务的当前设备结果，按“任务＋设备”一台次计数；不累加重试attempt。后端使用assignment当前结果查询，首页不重建完整执行历史。
- 证书包括有权查看的设备证书、平台服务证书与CA，按有效期统计当前使用记录，排除撤销、停用及已替换历史证书；按张数统计，明细与计数一致。
- 平台核心统计：设备总数为平台范围内未报废的设备，等于库存设备与出库设备之和；库存设备为库存状态“在库”的设备；出库设备为已出库设备；已激活设备口径同客户工作台，为未报废且激活状态为“已激活”的设备，包含已抽检激活、尚未出库的库存设备。各卡片点击进入对应设备明细，明细标题与卡片名称一致。设备列表中的库存状态取值仍为在库、已出库、报废。平台首页不单独统计防拆设备，平台按防拆状态在设备列表中查询。
- 库存设备与出库设备反映当前库存状态，非累计流转次数。
- 最近出入库以列表展示号段入库、批量入库、设备出库、退货回收记录，按操作时间倒序展示6条。每条显示操作类型图标、操作类型、目标机构、批次号、操作时间与成功／总数台数，存在失败时台数以橙色标示；点击进入流转记录详情，标题右侧“全部记录”进入流转记录。
- 激活趋势：按 UTC 日期统计近7天（默认）或近30天每日出厂激活与防拆激活次数，不含工厂激活；成功与失败堆叠展示，失败在上；最后一根为今日（截至当前），成功部分以斜纹区分。同一设备多次激活按次数计。
- 激活趋势上方显示所选范围内的激活成功次数、激活失败次数和成功率，均含今日；成功率为成功次数除以成功与失败次数之和，保留1位小数，无记录时显示“—”。悬停柱形显示日期、成功次数、失败次数、其中防拆激活次数与当日成功率；点击柱形进入当日激活记录，展示SN、激活类型、所属机构、激活结果、失败原因、激活时间，按激活时间倒序。
- 客户设备分布：以排行表展示，按出库台数倒序；不超过8个客户全部展示，超过8个展示前7个及“其他N个客户”。列为排名、客户、激活分布、出库、已激活、未激活、激活率；激活分布条形长度对应出库台数，按已激活、未激活两段显示，图例位于标题右侧；激活率为已激活除以出库台数，保留1位小数。窄屏隐藏已激活、未激活两列。点击客户进入客户详情，点击“其他”进入客户管理。
- 平台侧消息通知中的任务执行失败，范围为平台创建的任务及全部 Kernel 升级任务；证书提醒包括设备证书、平台服务证书与CA。
- 平台设备型号分布：提供“全部／库存”切换，默认全部。全部按设备总数口径分组，中心显示设备总数；库存按库存设备分组，中心显示库存设备数。分组、排序、占比与点击规则同设备型号分布，点击型号查看当前口径下该型号设备。
- 激活统计按激活类型、UTC 日期与激活结果统计，不用机构归属代替类型；失败明细展示实际失败原因。
- 原型业务日期沿用2026-09-13，日期和统计使用统一业务时钟；生产实现使用服务端统一时区、时间范围与统计时点。

后台实现约束：

- 设备数量、激活、触发防拆与超过7天未通信读取设备当前状态、防拆状态与 `last_seen_at`；型号分布按型号分组。
- 设备日活跃明细表 `t_device_active_day`：stat_date（UTC日期）、device_id、tenant_id、org_id、org_path，主键 stat_date + device_id。更新 `last_seen_at` 时，旧值的UTC日期早于当日则同时写入当日记录（INSERT IGNORE），每台设备每日最多写入一次。
- 设备日活跃汇总表 `t_stat_device_active_daily`：stat_date、org_id、active_count、device_total。每日 UTC 00:10 汇总前一日数据。趋势查询时，历史日期按授权机构的 org_path 汇总读取，今日数据读取明细表。
- 明细表保留90天，汇总表保留1年；超过明细保留期的日期不提供当日活跃设备明细。
- 激活趋势按激活记录的激活类型、结果与 UTC 日期分组统计，激活记录表建立 (activation_type, create_time) 索引。客户设备分布读取设备当前出库归属与激活状态；平台防拆设备读取设备防拆状态。
- 首页加载和手动刷新时查询，初期不要求秒级实时推送；经实际查询性能评估后可增加30—60秒短缓存。缓存键包含租户、有效数据范围及模块权限，避免跨范围复用。
- 同批设备统计共享过滤条件和统计时点。卡片与分类明细复用过滤口径，明细分页查询；生产环境查询期间数据可能更新，不能用隐藏超范围数据或改动权限来追求数字一致。

## 3. 设备管理

### 3.1 设备列表与详情

| 功能 | 内容 |
| --- | --- |
| 设备查询 | 按 SN、型号、所属客户／机构、设备模式、防拆状态等条件查询，支持分页、详情和导出。设备模式筛选项为调试、工厂、锁定、产品；防拆状态筛选项为未触发、已触发 |
| 列表统计 | 平台、客户、机构使用相同的四项统计：设备总数、已激活设备、锁定设备、触发防拆设备。统计范围为当前账户数据范围内未报废的设备，不随查询条件变化；设备总数与工作台“设备总数”一致，平台侧包含库存与已出库设备。锁定设备按设备回报的当前模式为锁定计数，不含仅待设置为锁定的设备；触发防拆设备为防拆状态“已触发”的设备。库存与出库情况通过库存状态列及平台工作台查看，列表统计不再单列已出库 |
| 列表字段 | 平台、客户、机构使用相同列：设备SN／型号、所属客户／机构、库存状态、激活状态、防拆状态、当前版本、操作。防拆状态为已触发时下方显示触发时间。当前模式与待设置模式在设备详情查看，列表按设备模式筛选；列只随数据范围变化，不按角色增减 |
| 基本信息 | SN、产品型号、所属客户、所属机构、备注 |
| 版本信息 | 出厂 Kernel、APP、参数版本，以及设备上报的当前版本 |
| 状态信息 | 库存状态、激活状态、当前设备模式、待设置模式、防拆状态、最近上报时间 |
| 详情页面 | 独立整页展示，顶部为设备概览卡，下方使用横向页签；从设备列表进入后，可返回原列表并保留筛选状态 |
| 顶部概览 | 标题区左侧为产品缩略图（固定小尺寸，不占整列），右侧为 SN、库存状态、激活状态标签（防拆已触发时追加红色标签）及“产品名称 · 型号”。下方分三组展示：归属信息（所属客户、所属机构、入库时间、备注；报废设备显示报废原因）；运行状态（当前模式、待设置模式、防拆状态及触发时间与原因、最近上报时间、最近激活时间）；版本信息（Kernel、APP、参数的当前版本，右侧标注出厂版本）。窄屏时三组上下排列 |
| 模式展示 | 当前模式以设备上报为准，未上报显示“—”；待设置模式为已发布、未完成的模式任务目标，无则显示“无”。执行中任务数显示在“任务记录”页签上 |
| 详情页签 | 任务记录、变更记录、通信记录、激活记录、设备证书、流转记录，默认进入任务记录。激活记录按激活记录查看权限展示，设备证书按证书查看权限展示 |
| 页签职责 | 设备当前状态由顶部概览承担；页签只展示按时间累积的记录，每个页签对应一张按设备查询的业务表，见下方“详情数据来源” |
| 任务记录 | 本设备参与的 OTA、RKI、模式任务：任务名称、类型、维护机构、目标（模式任务显示目标模式）、任务状态、本设备结果；按任务创建时间倒序，可进入任务执行详情；维护动作按任务创建机构与角色权限控制 |
| 变更记录 | 设备版本与状态的变化：变更时间、变更项（出厂版本、Kernel、APP、参数、设备模式、防拆状态、激活状态）、变更内容（变更前 → 变更后）、关联业务（OTA任务、激活记录、设备出库、设备上报、入库登记）；提供全部／版本／状态切换，关联到任务、激活记录或流转记录的可进入查看 |
| 通信记录 | 设备与平台交互的请求报文与响应报文，逐条展示交互时间与来源地址、命令、请求内容、响应码与说明、耗时，支持按命令筛选；点击“报文”查看该条的请求报文与响应报文；详见下文 |
| 激活记录 | 激活时间、激活类型、操作人、结果、失败原因，可进入激活记录详情 |
| 设备证书 | 证书用途、签发CA、序列号、有效期至、状态，可进入证书详情 |
| 流转记录 | 入库、出库、转移、回收、报废的逐台记录：操作时间、操作类型、批次号、原所属机构、处理后机构、操作人、结果；可进入有权限的批次详情 |
| 批量操作 | 勾选设备后发起出库、转移、退货回收或报废；模式设置仅平台提供操作入口；报废设备不提供新建任务入口 |

**设备模式与防拆状态规则：**

- 设备模式与防拆状态均以设备上报为准，平台不按任务或操作推断；设备任务查询、状态上报、激活请求、任务结果回传中携带的状态到达后更新。设备入库时模式为空，设备详情显示“—”，按设备模式筛选时不在任一模式结果中；防拆状态入库时为“未触发”。
- 设备模式取值为工厂、调试、产品、锁定。设备出厂为工厂模式；激活成功后设备上报为产品模式；执行锁定任务后上报为锁定模式；执行调试任务后上报为调试模式。
- 防拆状态取值为未触发、已触发。设备上报防拆触发时置为已触发，同时记录触发时间与触发原因；该设备完成防拆激活后由设备上报恢复为未触发。锁定、解锁等模式任务不改变防拆状态。
- 报废设备保留最后一次上报的模式与防拆状态，不计入各项统计。

**变更记录规则：**

- 平台记录的当前版本始终等于设备最近一次上报的版本。设备在任务查询、状态上报、激活请求等任何一次交互中都携带当前版本，平台比对后不一致才记录一次变更；系统没有单独的版本上报接口。
- 首条为入库登记的出厂版本基线。
- 设备上报的设备模式、防拆状态与平台当前值不同时记录一条状态变更；激活成功记录“未激活 → 已激活”；设备出库将激活状态重置时记录“已激活 → 未激活”，关联该出库记录。
- 出库前产生的变更记录仅平台可见；出库后的记录随设备当前归属可见。
- 新版本与该设备某个已回传成功的 OTA 任务目标版本一致时，填入关联任务并可进入执行详情；关联任务为空即表示平台未安排过这次变化（现场刷机、售后更换、版本回滚等），是运维需要关注的对象。
- 不单独设置“来源”列：是否为计划内升级由关联任务列是否有值表达，避免与关联任务重复表述。
- 任务执行结果与版本变更分别记录。回传成功但后续上报版本未变，说明升级未实际生效，在 OTA 执行记录中体现，不产生版本变更记录。
- 变更记录只读保留，不提供人工编辑入口。

**详情数据来源：**

| 页签 | 数据表 | 写入时机 | 查询方式 |
| --- | --- | --- | --- |
| 顶部概览 | 设备表 | 入库、出库、转移、激活及设备每次有效通信时更新当前值 | 按设备主键读取一行 |
| 任务记录 | 任务执行项表关联任务表 | 创建任务时逐台生成执行项，设备领取与回传时更新 | 按 device_id 索引查询，按创建时间倒序分页 |
| 变更记录 | 设备变更记录表（device_id、变更项、变更前、变更后、关联业务类型与编号、所属机构、变更时间） | 设备上报值与当前值比对不同时写入；激活成功、设备出库时写入 | 按 device_id + 变更时间索引查询，按变更项分组过滤 |
| 通信记录 | 设备报文记录表 | 设备接入服务完成一次请求与响应后异步批量写入，写入失败不影响设备交互 | 按 device_id + 交互时间索引查询，按日分区，保留 30 天后整区删除 |
| 激活记录 | 激活记录表 | 激活会话建立、完成或失败时写入 | 按 device_id 索引查询 |
| 设备证书 | 设备证书表 | 证书签发、吊销与状态变化时写入 | 按 device_id 索引查询 |
| 流转记录 | 流转明细表（批次号、device_id、原机构、目标机构、结果、原因） | 入库、出库、转移、回收、报废逐台处理时写入 | 按 device_id 索引查询，关联批次表取操作类型、操作人与时间 |

变更记录只在值变化时写入，写入量与设备状态变化次数相当；设备每次通信只做一次当前值比对，不额外查询历史。

**设备通信记录：**

记录设备与平台之间每一次请求与响应，按报文字段解析后保存，用于核对设备上送的内容和平台的应答。

| 字段 | 说明 |
| --- | --- |
| 交互时间 | 平台收到请求的时间，UTC 存储，按用户时区展示 |
| 来源地址 | 设备连接的 IP 与端口 |
| 命令 | 命令码及名称：10 更新请求、11 下载请求、12 安装完成通知、13 状态设置、A0 激活握手、A1 终端激活，后续新增命令按协议补充 |
| 请求内容 | 请求报文中除命令码、终端号、SN、长度、校验位外的前三个字段，下方显示关联的任务或激活类型 |
| 响应 | 响应码及说明，取值按接口规范响应码定义，如 00 成功、09 不需要更新、99 要求终端发起状态更新；平台内部错误使用独立错误码 |
| 耗时 | 平台收到请求到发出响应的时长 |
| 报文 | 弹出侧栏，标题为命令与交互时间，只展示请求报文与响应报文两部分；每部分列出全部字段的字段名、含义与值，并附十六进制原始报文，按下方规则脱敏或截断 |

保存规则：

- 10、12、13、A0、A1 的请求与响应逐条保存字段与原始报文。
- 11 下载请求逐包保存请求字段、响应码与数据长度，不保存下载数据内容，原始报文只保存报文头。
- 10 更新请求返回“09 不需要更新”时，每台设备只保留最近一条，新请求到达时覆盖。
- 授权码只保存末 4 位；传输密钥、签名、终端状态密文等密文字段只保存前后各 4 个字节及长度；A1 下发的密钥数据、A3 密钥块、下载数据不保存。
- 列表按交互时间倒序分页，支持按命令筛选。
- 每条记录另存关联编号（与接口访问日志一致）与关联业务编号，用于链路追踪和列表中的关联显示。
- 记录保留 30 天，按日分区到期整区删除。查看权限随设备查看权限；导出按日志导出权限单独授予。

### 3.2 入库、出库与流转

| 功能 | 内容与规则 |
| --- | --- |
| 号段入库 | 一次可添加多个号段，每行填写完整起始 SN 和数量，自动显示结束 SN；统一选择本次产品型号和出厂版本，填写备注；支持增删号段并汇总数量，跨号段重复 SN 逐台记录失败 |
| 批量入库 | 下载 Excel 模板，填写后导入；字段为 SN、型号、Kernel版本、APP版本、参数版本、备注，不包含品牌；支持 Excel／CSV 预览与校验，旧版含品牌列的文件提示更换模板 |
| 入库校验 | 校验 SN 格式、批次内重复、系统已有 SN、型号合法性等，逐台返回处理结果 |
| 设备出库 | 平台将库存设备分配给目标客户；校验库存归属及客户是否已获该型号授权。出库时设备激活状态置为“未激活”，抽检阶段签发的设备证书同步吊销，工厂激活记录保留；到货后由客户执行出厂激活 |
| 设备转移 | 在同一客户内向授权范围内的下级机构转移；选择目标机构并提供 SN，无须额外填写源机构 |
| 退货回收 | 将客户设备回收到平台库存，保留历史归属、任务和流转记录；回收后可再次出库给其他客户 |
| 设备报废 | 填写报废原因，标记报废并保留原所属客户、原所属机构及历史记录；不自动回收到平台库存，不计入可用库存；报废设备不能再进入正常任务和流转流程 |
| 撤销转移 | 满足未配置任务、未发生后续流转等条件时，由原转出机构撤销；设备恢复原归属 |
| 批量处理结果 | 支持部分成功；失败设备保留原状态并记录原因，可查看或导出失败明细 |

出库、转移、退货回收、模式设置和报废统一支持“按条件筛选”和“按 SN 清单”选择设备。可按机构及下级、型号、当前模式、库存状态和 SN 关键词筛选，逐台勾选或选择全部筛选结果；两种方式共用已选列表，合并去重并支持移除、清空。修改筛选条件不自动扩大已选范围。提交时仍逐台校验设备是否满足当前操作条件。

退货回收页面提示文案：回收到平台库存，保留历史归属及流转记录。

流转前校验待执行、执行中任务及其他阻断业务。存在冲突的设备处理失败，不强行变更归属，也不自动停止原任务。

### 3.3 流转记录

- 统一查询号段入库、批量入库、出库、转移、退货回收、报废等操作记录。
- 记录批次号、操作类型、来源／目标机构、总数、成功数、失败数、操作人、操作时间和备注。
- 批次详情逐台展示 SN、处理结果和失败原因。
- 按机构归属识别转入和转出记录；符合条件的转移记录提供撤销入口。

### 3.4 设备分组

分组是业务设备集合，用于 OTA 选择目标设备，不代替客户／机构归属。一个设备可加入多个分组，同一分组内不能重复关联。

| 功能 | 内容与规则 |
| --- | --- |
| 页面结构 | 左侧分组目录，支持按分组名称或维护机构查询；右侧显示分组概览、已关联设备和关联记录 |
| 分组概览 | 顶部仅显示分组名称、所属机构、只读标识及有权限的编辑／删除操作，不展示备注和统计卡。设备数量保留在左侧目录与设备列表分页区域；型号通过列表及筛选查看。备注可在编辑中维护 |
| 分组维护 | 新建、编辑、删除；同一机构内分组名称唯一；仅分组所属机构的授权人员维护，上级可按数据范围只读查看 |
| 已关联设备 | 按单台设备展示 SN、型号、所属机构、当前模式、库存状态，支持查询、分页、详情和导出；号段作为输入方式，不作为设备归属单位 |
| 筛选添加 | 按 SN、型号、机构、模式和库存状态筛选，勾选设备或选择全部筛选结果；候选列表排除已在当前分组内的设备 |
| SN／号段添加 | 粘贴 SN 清单，或输入完整起始 SN 和数量生成设备清单，再匹配授权范围内的现有设备 |
| 批量关联 | 上传单列 SN 的 Excel／CSV 文件，提供 CSV 模板；先校验预览再确认关联，支持部分成功 |
| 关联校验 | 校验设备存在、分组机构数据范围、报废状态；已在当前分组的设备跳过，不重复添加；未知或无权限设备返回失败原因 |
| 移出分组 | 支持单台和批量移出，仅解除当前分组关系，不改变其他分组、设备归属及已发布任务 |
| 关联记录 | 记录加入／移出时间、操作人、总数、成功／跳过／失败数量，提供逐台详情和失败明细导出 |
| OTA 使用 | 创建 OTA 时加载当前分组内仍处于授权范围且未报废的适配设备；发布后分组变更不反向调整任务设备名单 |
| 删除限制 | 被任务引用的分组限制删除；设备转出分组机构的管理范围后，不再作为该分组的可选任务目标，历史记录保留 |

### 3.5 设备模式任务

- 设备模式为工厂模式、调试模式、产品模式、锁定模式四种，列表筛选提供全部四种模式。
- 模式变更规则：任何模式都不能变更为工厂模式；工厂模式只能变更为调试模式或产品模式；调试、产品、锁定三种模式之间可以互相变更。
- 模式任务的目标模式只提供调试、产品、锁定三种。选择设备时按所选目标模式只列出允许变更的设备；提交时逐台校验设备当前模式，模式未上报、当前模式与目标相同或不满足变更规则的设备不能提交，提示SN及原因。
- **模式设置仅平台可操作**。客户与下级机构不分配模式任务菜单及创建、发布、停止等操作权限；可只读查看设备当前模式、待设置模式及本设备相关结果。
- 设置模式采用单页表单：任务名称、目标模式、设备选择、备注集中填写，目标模式下方显示变更规则；底部提供保存草稿、发布任务，不使用分步向导。
- 支持平台维护草稿、发布、停止、复制及查询详情。发布任务只登记待执行的目标模式，不立即修改设备当前模式。
- 发布后等待设备主动查询、执行和反馈；仅创建任务不改变设备实际模式。
- 终端开机自检时向平台查询应处模式，与本地模式不一致时执行同步；同步完成后由设备上报当前模式，平台据此更新。
- 锁定模式与防拆状态相互独立：锁定由平台模式任务设置，通过将设备设置为调试或产品模式解除；防拆触发由设备上报，通过防拆激活解除。两者使用各自的字段、入口与记录。
- 展示逐台执行结果及失败原因，不设置任务有效期。

## 4. 远程维护与密钥分发

### 4.1 升级包管理

采用“升级内容 → 版本列表”两层结构。同一升级对象的多个版本集中在同一内容下，不以文件名作为内容身份，也不把每个版本平铺到一级列表。

一台设备只有一个 Kernel、一个应用和一套参数，不存在需要区分升级哪一个的情况，因此不设置“应用标识／参数用途”属性：升级类型本身已经能唯一指向升级对象。

| 功能 | 内容与规则 |
| --- | --- |
| 内容列表 | 内容名称、类型、适配型号、可用范围、维护机构、最新上传版本、版本数量；专用内容在列表中带标记，便于与通用内容区分 |
| 内容身份 | 以维护机构、类型、适配型号和客户可见范围区分内容；系统保存稳定内容标识，同名文件不自动合并 |
| 内容唯一 | 同一维护机构、类型、型号和客户范围下只存在一个升级内容；重复创建时提示进入已有内容上传新版本，不允许并存两个语义相同的内容 |
| 创建内容 | 填写内容元数据并上传首个版本；可编辑内容名称和描述，类型、型号与客户范围创建后保持不变；不增加空内容创建步骤 |
| 版本列表 | 展示版本号、文件名、大小、版本说明、上传时间、可用／停用状态；支持上传新版本、查看详情、启停及受限删除 |
| 版本规则 | 同一内容下版本号唯一；保存后不覆盖文件、修改版本号或改变型号，修订文件须上传新版本；“最新上传”按上传时间判定，不代表推荐升级或最高语义版本 |
| 任务引用 | 每个任务引用具体版本记录，新增版本不改变旧任务；已被任务引用的版本不能删除；停用后禁止新建或发布引用该版本的任务，已发布任务按原版本继续 |
| 平台权限 | 平台可维护自己创建的 Kernel、APP、参数内容，创建全部三类 OTA 任务；类型权限不代表可修改客户创建的资源或任务 |
| 客户权限 | 客户及机构按角色维护本机构 APP／参数内容；Kernel 由平台维护，获授权客户可以使用适配 Kernel 创建任务 |
| 可用范围 | 平台新建内容时选择“通用内容”或“指定客户”，创建后不可修改。通用内容对所有获该型号授权的客户可用；指定客户即为该客户专用内容 |
| 专用内容约束 | 专用内容及其全部版本只对该客户及其下级机构可见、可用；平台自己创建任务时同样只能选择该客户的设备。范围按客户（租户）判定，不细分到机构——设备在客户内部可自由转移，按机构限制会在转移后失效 |
| 客户自建内容 | 客户及机构创建的 APP／参数内容天然属于本客户，不提供可用范围选项，始终保持客户隔离 |
| 范围与适配 | 可用范围决定“谁能看见、谁能用它建任务”，适配型号决定“哪些设备能装”，两者分别校验，不互相替代 |
| 使用校验 | 校验版本状态、型号适配、客户型号授权及内容访问权限；文件校验值由文件服务计算并保留 |
| 传输要求 | 除激活握手（A0）与终端激活（A1）外，终端与平台之间的其他接口调用全部走 TLS。A0／A1 不能走 TLS 是因为终端 TLS 密钥对正是在 A1 时才下发的 |

### 4.4 RKI 密钥管理

| 功能 | 内容 |
| --- | --- |
| 密钥与任务分离 | 密钥导入与 RKI 下发任务是两个独立动作，不合并为“建任务时上传密钥”。理由：导入由密钥操作员执行、下发由运维执行，权限不同；同一批密钥可分批下发无需重复经手材料；失败项重试要求沿用同一材料版本；入库与下发需要分别追溯 |
| 导入表单 | 按密钥类型驱动。类型只有三种：TMK、IPEK、Fixed Key |
| 不含工作密钥 | PIN／MAC／数据等工作密钥不在此导入、也不经 TMS 远程注入。MK/SK 体系下工作密钥由收单主机在终端签到时用 TMK 加密下发，走交易链路，与 RKI 无关 |
| 不绑定型号 | 密钥按 SN 逐台导入，文件中的 SN 已唯一确定设备及其型号，不再单独设置适配型号——重复约束且会挡住跨型号的密钥批次 |
| 导入方式 | 仅支持密文文件，不提供明文选项、方式切换或解密配置。导入不自动下发，仍由RKI任务执行 |
| 导入字段 | 密钥类型、密钥索引、文件解密算法、解密密钥长度、分量数量、各分量及KCV、合成密钥KCV、密文文件、备注。无批次名称，无设备密钥算法输入；内部标识由系统生成 |
| 文件解密算法 | 选项仅显示TDES-ECB、TDES-CBC、AES-ECB、AES-CBC、AES-KW，不加括号说明，不默认选择。TDES解密密钥16／24字节，AES为16／24／32字节。ECB／CBC统一约定NoPadding；CBC由文件每行提供IV（TDES为8字节，AES为16字节），不设置整文件公共IV。AES-KW使用RFC3394，不填写IV。解密算法必须匹配客户格式；ECB／CBC为客户兼容格式，不据此宣称满足密钥块传输规范，当前不解析TR-31 |
| 密钥分量 | 提供2／3个分量，默认2个；不设1个“完整密钥”选项。各分量为相同长度的十六进制独立分量，按字节XOR合成文件解密密钥（KEK），不是把一把密钥截成数段。分量不下发设备，不能与每台设备的TMK／IPEK／Fixed Key混淆 |
| 分量校验 | 每个分量及合成密钥均填写6位KCV。原型只校验格式、长度、零值和重复分量；服务端另校验每个分量KCV、合成密钥KCV、弱密钥及解密结果。任一分量或合成KCV失败则整次拒绝，不能逐行跳过该错误。修改算法、长度或数量时清空全部分量及KCV |
| KCV约定 | 本方案TDES采用加密8字节零块取前3字节，AES采用对16字节零块计算CMAC取前3字节；均显示6位十六进制。须与客户约定一致，不能将不同KCV算法混用。文件中逐台密钥的KCV按该设备密钥算法计算，不能直接套用文件解密算法。参照[AWS Payment Cryptography术语与KCV说明](https://docs.aws.amazon.com/payment-cryptography/latest/userguide/terminology.html) |
| 密钥文件 | UTF-8 CSV，首行为固定表头，一行对应一个SN的一份密钥；最多10000条、5MB，SN及十六进制值按文本处理保留前导零。三种类型表头见下表；CBC额外在KCV前插入IV列。密钥索引、解密算法、长度、分量及分量KCV由表单统一填写，不重复放入文件。KCV列为设备目标密钥的校验值，与分量KCV和合成密钥KCV不同。SN重复拒绝重复行；格式合法后还须校验授权、设备状态、客户算法约定、解密结果与目标KCV。支持逐行部分成功，错误不回显密钥 |
| 分量保护 | 密码框输入，禁止回显、持久化到浏览器或日志、带入导入结果与编辑详情；服务端只在受控导入会话内处理分量和合成密钥，完成／失败／取消／超时后释放敏感材料。单人在同一表单输入所有分量不等于双人控制；正式生产应由不同保管人在独立认证会话逐份提交，以导入会话关联，客户端不得收集其他保管人的分量。当前单表单仅用于交互评审，本期纯软实现不能据此宣称满足PCI PIN密钥仪式要求 |
| 列表与详情 | 列表显示密钥类型、索引、状态、导入时间及操作，移除导入方式。编辑与详情同步移除导入方式，展示文件解密算法、长度、分量数量、文件字段及逐台明细；编辑仅修改备注。历史缺失参数显示未记录，不猜测补值，不回显密钥分量 |
| 编辑 | 仅修改备注，变更密钥材料必须重新导入 |
| 原型边界 | HTML仅演示分量输入及CSV基础格式校验，不执行XOR密钥合成、解密、KCV计算或真实密钥存储。检查按钮标注“检查输入格式”，结果明确提示尚未验证KCV，不用“校验成功”代替密码学校验 |
| DUKPT 边界 | 只接收客户按设备提供的 IPEK 与 KSN，**不接收 BDK、不做派生**。一把 BDK 可派生该客户全部设备的 IPEK，本期纯软实现、无加密机，不宜由平台持有；接入加密机后可重新评估 |
| 逐台材料 | 密钥按设备存放：一个批次下是若干台设备各自的密钥材料。密钥详情展示“密钥导入明细”：设备SN、所属机构、密钥索引、KCV，IPEK另有KSN。明细表示设备已有对应密钥材料，不表示已创建任务或已下发；不展示待下发、执行中、成功、失败等下发状态。RKI任务按设备绑定对应材料，执行状态、执行次数、时间和失败原因在RKI任务详情及RKI执行记录中查看，同一材料的多次下发分别归属对应任务 |
| 密钥体系 | 本页类型映射：TMK → MK/SK，IPEK → DUKPT，Fixed Key → Fixed Key。MK/SK工作密钥不在本页导入；Fixed Key具体用途沿用客户协议约定 |
| 密钥算法与索引 | 算法由客户接入约定确定，不在页面录入或展示。索引为两位十六进制（00-FF），指密钥在设备安全芯片中的**槽位**；格式不合法时拒绝保存 |
| 两个“密钥索引”不要混淆 | 密钥自身的槽位索引（本页配置的）与密钥下载报文中的**下载序号**是两个字段。下载序号从 0 开始，终端每成功一项按服务器返回值加 1，用于下载中断后的断点续传，不由本页配置 |
| 密钥维护 | 查询、查看详情、维护备注、启用／停用 |
| 数据隔离 | 密钥资源按客户隔离，默认由银行／支付机构获授权的密钥人员操作。平台租户可开通密钥与 RKI 菜单，但内置平台管理员角色不含这些菜单的权限项，平台人员需由自定义角色显式授予；菜单开通与权限授予分开控制 |
| 敏感信息保护 | 页面只显示批次信息、设备 SN、索引、KCV 和状态，不展示或导出支付密钥内容；原始密钥文件解析入库后不长期保留，导入结果与错误明细也不回显密钥内容 |

三种密钥文件模板：

| 密钥类型 | ECB／AES-KW表头 | CBC表头 |
| --- | --- | --- |
| TMK | SN,TMK密文,KCV | SN,TMK密文,IV,KCV |
| IPEK | SN,IPEK密文,KSN,KCV | SN,IPEK密文,KSN,IV,KCV |
| Fixed Key | SN,FixedKey密文,KCV | SN,FixedKey密文,IV,KCV |

- 密文、IV、KSN、KCV均为十六进制，无0x前缀。下载模板随所选类型和算法更新，切换算法清空已选文件，避免误用模板。
- TDES-ECB／CBC密文按8字节对齐；AES-ECB／CBC按16字节对齐；AES-KW至少24字节且为8字节倍数，服务端还须校验包装完整性。使用NoPadding时不满足对齐的目标密钥不能通过自行补零导入，应使用双方约定的兼容格式。
- IPEK文件不含BDK；保留现有IPEK页面类型名称，TDES体系KSN为20位十六进制，AES体系为24位。前端允许两种长度，服务端按客户设备密钥体系精确校验；不能按文件解密算法推断DUKPT体系。
- Fixed Key具体用途由客户与设备协议确定；若同一SN需导入多个用途或槽位，分次导入，当前单文件不支持同一SN多行。

### 4.5 RKI 任务与执行记录

- 后台选择授权密钥及目标设备创建 RKI 任务，设备主动查询后执行密钥下载。
- 支持草稿、发布、停止、复制、草稿删除、任务详情和进度查询。
- **RKI 不设置任务有效期，不提供永久开关和起止日期。**
- 按任务、SN、型号、机构和结果查询RKI执行记录，查看逐台失败原因并导出授权范围内的记录。
- 菜单统一命名为“RKI执行记录”，与“RKI任务”“OTA执行记录”对应。列表及导出显示任务名称、设备SN、型号、所属机构、结果、失败原因；列表提供任务详情入口。移除“密钥版本”列，内部材料标识与版本仍保留用于任务绑定和审计追溯，不作为面向操作员的展示列。
- RKI 菜单与操作权限单独授权；普通运维、监控和工厂人员不默认获得 RKI 业务权限。密钥管理、RKI 任务、RKI 执行记录三个菜单不进入任何内置角色，平台与客户人员都必须通过自定义角色显式授予。

## 5. 激活与证书

### 5.1 激活授权

人员激活资格与单次授权码分开管理。前者决定“这个账户能激活哪些设备、资格何时到期”，后者决定“本次允许激活哪台设备”。

| 功能 | 内容与规则 |
| --- | --- |
| 账户复用 | 激活工具使用系统成员账户，工具登录会话与单次设备激活授权分开 |
| 授权维护 | 配置授权名称、已有账户、设备范围、人员授权有效期、累计激活额度、已发起会话数和状态 |
| 机构设备 | 对售后人员可选“人员所属机构及下级机构”；选中后只显示机构范围说明，不显示 SN 输入框；每次使用仍需校验当前数据权限 |
| 指定设备 | 选择“指定设备SN”才显示必填 SN 清单；校验存在、归属、报废状态及人员可访问范围；清单是机构范围内的进一步限制 |
| 工厂范围 | 平台工厂账户只提供指定设备 SN，且须属于平台库存；设备出库后不能继续沿用工厂库存授权。售后设备由当前客户／机构人员授权处理 |
| 菜单归属 | 激活授权与授权码记录**不属于平台边界**，对客户开放：客户及机构在授权范围内为本机构售后人员配置激活资格、申请与撤销授权码。平台侧只处理平台库存设备的工厂激活授权 |
| 授权调整 | 可调整范围、累计额度及有效期；累计额度不得低于已发起会话数；修改授权后撤销该授权下待使用授权码，已开始会话按会话规则处理 |
| 累计额度口径 | 每次成功建立新的激活会话扣减一次；申请后未使用、到期、被撤销不扣减；同会话重连不重复扣减。激活失败后重新建立会话需新的授权码，累计额度相应计数 |
| 账户停用 | 限制后台与工具访问，撤销仍待使用授权码；授权本身停用同样阻止新的激活会话 |

### 5.2 一次性授权码与激活业务

原需求明确工具用户名／密码登录、SN 合法性检查和激活处理，没有规定授权码可重复使用。原页面的“单码允许次数／已使用次数”取消，采用以下建议方案：

1. **授权码在 TMS 管理后台（WEB 端）申请**，不单独开发认证工具。申请时选择激活授权，系统校验账户、人员授权与剩余额度后发放；申请人取走授权码后在激活工具中使用。若申请时已连接设备可填写 SN，平台提前校验设备范围与状态；尚未连接设备的可留空。
2. 授权码绑定账户与激活用途；设备绑定发生在申请时（已提交 SN）或首次发起激活时（按请求携带的 SN 绑定）。一旦绑定不能更换设备，一码只允许建立一次激活会话。
3. 同一账户同时只保留一个未使用授权码，新申请自动撤销该账户上一个未使用的码，避免批量囤码后脱离设备范围校验使用。
4. 授权码过期时间默认建议为发放后 **10 分钟**，最终由服务配置确定；这是产品建议，不是标准规定的固定时长。过期时间只约束授权码本身，即在此之前必须发起激活会话；会话建立后的超时另行管理，授权码过期不影响已建立的会话。过期且未使用的授权码失效。
5. 第一次合法请求原子校验并占用授权码，未绑定设备的在此刻完成设备绑定与设备范围、状态校验，同时建立会话；不能等到激活成功后才消费授权码，否则可能重复并发使用。
6. 网络重传／断线恢复使用同一会话标识处理，不能再次凭该码创建会话，也不能换设备使用。会话超时与授权码过期时间分别管理。
7. 激活失败不恢复授权码可用状态；原会话可恢复时继续，否则重新申请。新申请按第 3 条撤销该账户上一个未使用的码。
8. **授权码发放渠道可配置，两种都支持**：`tool` 为申请人在后台取码后交激活工具使用（建议默认值，也是私有化部署无邮件服务时的唯一可用渠道）；`email` 为平台将授权码发送到申请账户已验证的邮箱。配置粒度到客户，平台可设默认值。启用 `email` 时要求账户邮箱已验证，未验证则拒绝申请并提示，不静默回落到 `tool`。两种渠道共用同一套申请校验、绑定、额度、过期与撤销规则，只有交付方式不同。若后续保留邮箱二次验证，其验证码与设备激活授权码分开命名和管理。

**授权码记录页面：**申请账户、绑定设备 SN、脱敏授权码、发放渠道、申请时间、过期时间、使用时间、授权码状态、关联激活会话及激活结果；支持查询、详情和撤销待使用授权码。绑定设备 SN 可为空，表示已取码但尚未发起激活，列表显示“待绑定”，详情区分“申请时已绑定”与“首次发起激活时绑定”。

授权码状态：待使用、已使用、已过期、已撤销。已使用只表示激活会话已建立，不代表激活成功。

**激活由终端发起，分两步：**

1. **A0 激活握手**：终端上送授权码、SN 与传输密钥密文，平台校验后返回随机数与签名。
2. **A1 终端激活**：终端携带状态与自毁原因发起激活，平台下发终端模式、激活结果以及 Term／Term_TLS／Term_RKI 三套密钥对。

**A1 必须在 A0 完成后 5 分钟内发起**，超时平台清除握手数据，本次激活失败需重新握手。终端侧另有自身超时（启动后 10 分钟内未完成即销毁密钥并结束通讯），与平台的授权码过期时间分别计算。

激活发生在三种情况：**整机组装阶段抽检**（工厂激活，仅抽检设备，测试完成后还原再出货）、**设备出库后客户首次启用**（出厂激活）、**触发防拆自毁后恢复**（防拆激活）。平台不能远程发起激活，全部由终端／工具主动发起；系统也没有“远程解锁”这一动作。

### 5.3 设备激活记录

- 查询 SN、型号、激活类型（工厂激活／出厂激活／防拆激活）、账户／操作人、激活时间及处理结果。
- 记录防拆／自毁原因和失败信息，关联授权码与会话；不显示授权码明文。
- 在详情查看身份校验、激活处理、证书及初始化数据写入、设备确认等步骤结果。
- 区分激活失败与初始化未完成；支持筛选、详情与导出。

### 5.4 CA管理

终端协议中平台侧持有三对 CA 密钥，CA 管理按**用途**组织，不按证书层级组织。终端出厂预置的是 CA 公钥本身，激活与认证报文直接用该公钥验签和加密，**不做证书链验证**，因此不设根 CA／签发 CA 的层级结构。

| CA 用途 | 协议密钥名 | 在协议中的使用 |
| --- | --- | --- |
| 激活 CA | `CA_PK` / `CA_SK` | A0 握手：用 CA_SK 解密终端上送的 `TransKey_RSA`，取出传输密钥与随机数A；A0 响应：对 `SHA256(SN+RandomA+RandomB)` 签名；A1 激活响应：对 `SHA256(SN+RandomA+终端状态+激活结果+密钥标志+Term_SK+Term_PK)` 签名；A2 认证（认证类型 0）：解密请求密文并对响应签名 |
| RKI CA | `RKI_CA_PK` / `RKI_CA_SK` | A2 认证（认证类型 1）：解密终端用 RKI_CA_PK 加密的请求，并对响应签名；RKI 认证响应：对 `RandomB + KBPK + RandomR + 密钥总个数` 的回包签名 |
| TLS CA | — | 签发终端 TLS 证书与 KDH 服务端证书，用于 TLSv1.2 双向认证 |

密码学参数由协议固定：报文中签名与密文字段均为 256 字节，对应 **RSA-2048**，签名与加密均为 **PKCS#1 v1.5**，摘要为 **SHA256**。页面不提供算法与长度的自由选择。

| 页面功能 | 内容与规则 |
| --- | --- |
| CA 列表 | 按 CA 用途、名称、密钥算法、公钥指纹、有效期和启停状态展示；证书主体、私钥持有情况、终端预置状态在详情中查看。每个用途同时只允许一条启用中的 CA |
| 自签生成 | 填写证书通用名 CN、组织 O、国家／地区 C 和有效期，平台生成密钥对并自签，提交后即生效。密钥算法 RSA-2048、签名算法 SHA256withRSA、填充 PKCS#1 v1.5、基本约束 CA:TRUE、密钥用途含证书签名／数字签名／密钥加密，均由协议固定，页面只读展示不可选择；密钥用途之所以包含数字签名与密钥加密，是因为该 CA 私钥还要直接解密握手密文并对激活报文签名 |
| 导入密钥对 | 导入 PKCS#12 或 PEM 格式的 CA 密钥对并填写私钥保护口令，文件必须包含私钥。用途是平台迁移、重建和私有化交付：存量终端预置的是原 CA 公钥，只有导入原来那把密钥对，这批设备才能继续激活。不提供只导入公钥的方式——本平台的每一项 CA 用途都需要私钥参与解密与签名，只有公钥无法承担 |
| 导出公钥 | 导出 CA 公钥（含用途、协议密钥名、算法、指纹），交终端产线预置。这是 CA 管理的必备动作——终端预置的公钥与平台 CA 不一致时，A0 验签与 A2 认证都会失败 |
| 终端预置状态 | 取值“待预置／已交付产线／不适用”。标记为已交付产线后不允许停用或更换该 CA：已出厂设备预置的是这把公钥，更换会使这批设备无法完成激活握手与认证 |
| 更换 CA | 需先停用原 CA 才能为该用途新建。停用前须确认没有存量设备依赖该公钥 |
| 操作追溯 | 生成、导入、停用、标记产线预置等动作统一记入操作日志（见 6.6），CA 页面不再单设申请记录面板——本期没有需要等待的在途状态，记录会与 CA 列表完全重复 |
| 私钥在线要求 | CA 私钥在激活与 RKI 流程中每台设备每次都要使用（解密 + 签名），必须在线可用，不能离线保管。加密存储、主密钥与密文分开存放、仅在服务内解密使用；签名与解密统一走密码服务接口，后续接入加密机时只替换实现 |

**待决事项（影响私有化部署）：** 终端出厂预置的公钥决定平台必须使用哪套 CA。私有化部署若由客户实例自行生成 CA，而终端预置的是厂家 CA 公钥，A0 验签与 A2 认证都会失败。需与终端方确认预置公钥能否按客户定制、终端是否支持证书链验证，再决定采用按客户预置、厂家根签发子 CA 还是在线签发方案。

### 5.5 设备证书

| 场景 | 签发与页面行为 |
| --- | --- |
| 工厂激活与出厂激活 | 在 SN、账户授权与设备身份校验通过后，按需签发设备身份和 RKI 设备证书，下发并等待设备确认；后台自动建立与 SN 的关联记录。出厂激活重新签发证书，不沿用抽检阶段证书 |
| 防拆后重新激活 | 先检查证书及对应私钥是否仍有效且可用；私钥已清除、证书到期、失效或用途变化时重新生成密钥／签发证书；满足复用条件时不机械地重复签发 |
| 签发重复请求 | 同一次激活会话复用同一签发结果，避免网络重传产生多份证书；已签发但设备尚未写入时保留待下发／待确认状态 |
| 证书用途 | 与 CA 用途一一对应：设备身份证书（`Term_PK / Term_SK`，由激活 CA 签发）、RKI 证书（`Term_RKI_PK / Term_RKI_SK`，由 RKI CA 签发）、TLS 证书（`Term_TLS_PK / Term_TLS_SK`，由 TLS CA 签发） |
| 下发时机 | 三套密钥对全部在终端激活（A1）时一次性下发，不分批、不在 RKI 阶段补发。RKI 阶段下发的是支付密钥，不是这三套身份密钥 |
| 管理页面 | 按 SN、型号、机构、证书用途、签发 CA、状态和有效期查询，详情展示颁发者、对应协议密钥和证书来源；通常不设置“批量提前生成设备证书”入口 |
| 证书来源 | 取值“工厂阶段下发”与“售后恢复下发”，两者均为平台签发 |
| 密钥生成位置 | 优先由终端安全区域生成私钥并提交公钥／CSR；如设备能力或既定初始化机制要求服务端生成，必须另行设计安全封装与注入，不能把私钥当作证书附件导出 |

证书签发完成、设备写入完成、激活成功分别记录，不混为一个成功状态。证书只绑定公钥及身份，不包含用于公开展示的私钥。

### 5.6 平台服务证书

菜单名由“服务端证书”改为“平台服务证书”，与“设备证书”对称：一边是发给终端的证书，一边是平台自己的服务使用的证书。

**先明确协议里不需要什么：** 激活服务和 RKI 服务的身份不是靠单独的服务端证书证明的，而是靠 `CA_SK` / `RKI_CA_SK` 对报文签名、终端用出厂预置的公钥验签。因此不设“激活服务身份证书”“RKI 服务身份证书”这两个用途。若未来终端支持证书链验证，可改为由 CA 签发独立的服务签名证书，届时换钥只影响一张叶子证书，不需要重建信任链。

| 证书用途 | 作用 | 签发方 |
| --- | --- | --- |
| 设备接入服务 | RKI 流程 B 步与终端建立 TLSv1.2 双向认证时下发的 `CERTkdh`，终端据此验证平台身份 | 平台 TLS CA |
| 管理后台 HTTPS | 浏览器访问管理后台的域名证书，与终端协议无关 | 公开受信任 CA，签发后导入 |
| 内部服务 TLS | 平台内部服务之间的 TLS 通信 | 平台 TLS CA |

| 页面功能 | 内容与规则 |
| --- | --- |
| 列表 | 按证书用途、名称、服务主体、签发方、有效期和启停状态展示，可按用途筛选 |
| 平台签发 | 选择用途、填写服务主体 CN／域名和有效期，由当前启用的 TLS CA 签发，提交后即生效。没有启用中的 TLS CA 时不允许签发，提示先去 CA 管理配置 |
| 导入证书 | 上传 PKCS#12 或 PEM 格式证书并填写私钥保护口令，文件必须包含私钥——服务端要用它完成 TLS 握手 |
| HTTPS 强制导入 | 选择“管理后台 HTTPS”时来源自动锁定为导入并说明原因：平台自建 CA 签发的证书浏览器不认，必须使用公开受信任 CA 签发的证书 |
| 密码学参数 | RSA-2048、SHA256withRSA、密钥用途为数字签名与密钥加密、扩展密钥用途为服务端身份验证，页面只读展示 |
| 续期与换证 | 到期前签发或导入新证书并启用，原证书停用；不在设备激活时才临时生成服务端证书 |
| 私钥 | 由部署组件绑定使用，页面不展示、不导出 |
| 操作追溯 | 签发、导入、停用记入操作日志（见 6.6），页面不单设申请记录面板 |

当前 HTML 展示本地页面交互，不实际签发证书、生成私钥或部署证书；这些能力在后端阶段实现。

## 6. 系统管理

### 6.1 客户管理与功能授权

- 创建、编辑、查询、启用／停用客户，维护客户名称、联系人、联系电话、国家／地区、省／州、城市和备注；**不保留客户联系邮箱属性**。
- 为客户配置可使用的产品型号，支持多选；存在归属设备或业务引用时限制取消关联。
- 配置客户管理员账号、昵称和初始密码；账号创建后保持稳定，密码通过专门的密码管理操作维护。管理员个人邮箱在成员管理中维护，与客户资料分开。
- 平台通过客户列表的“功能授权”入口配置客户可用菜单；工作台保留，设备、OTA、RKI、机构与成员等客户功能按实际交付范围开通。
- 平台边界为客户管理、产品型号、设备模式任务、CA、平台服务证书五个菜单，以及设备菜单中的入库、出库、退货回收三个操作，客户功能授权中不提供这些选项。边界按权限项标注，不是整菜单一刀切：设备菜单本身对客户开放，只是出入库操作保留给平台。激活授权与授权码记录**不属于**平台边界。
- 平台自身同样适用该功能授权模型：平台是固定客户，其可用菜单初始化为全部菜单，不提供平台功能授权配置入口。平台与客户的菜单可见性由统一的权限目录标注决定，不按账户类型写死名单。
- 客户可用功能是上限，具体成员还需要角色权限；开通 RKI 不代表所有客户成员自动获得密钥操作权限。
- 关闭功能后限制新的人员访问与操作，保留业务数据和角色配置，不自动停止已发布设备任务。再次开通后，原角色中保留的授权可恢复生效，保存时应明确提示影响范围。
- 已存在设备、任务或下级机构的客户限制删除；停用组织限制人员访问、使相关登录会话失效，不自动锁定设备。

### 6.2 机构管理

| 功能 | 内容与规则 |
| --- | --- |
| 机构目录 | 左侧按层级展示权限范围内的机构树，每个节点右侧显示该机构及下级的机构数；默认不选中任何节点，右侧展示全部授权范围内机构 |
| 节点筛选 | 点击节点只看该机构及下级，再次点击同一节点恢复全部。选中状态只由树中的高亮表达，不额外显示已选机构标签或“取消选中”按钮，操作方式写在目录标题下的提示中 |
| 范围提示 | 右侧列表的记录数行前缀当前范围，例如“东区分行及下级 · 2 条记录”；未筛选时只显示记录数。其他关键词筛选与机构筛选叠加生效 |
| 上级选择 | 新增机构使用可搜索的机构树选择器，显示层级与完整路径；只允许选择可管理、已启用的上级机构；不提供跨客户或任意输入机构编号 |

| 创建子机构 | 直接创建子机构及其管理员账户，管理员权限不得超过创建方可授予范围。本期不提供邮件邀请方式，统一走直接创建 |

### 6.3 成员与账号管理

**建议账号与邮箱分开，当前页面按此方案实现。** 账号作为稳定登录标识，邮箱作为可变更并需验证的联系方式，适用于银行、海外客户、工厂工具及私有化部署场景；不强制每个工厂人员具备邮箱。

| 字段／流程 | 规则 |
| --- | --- |
| 登录账号 | 必填，在本系统实例内唯一，创建后普通编辑不能更改；不随邮箱变更而改变。建议限制为3至64位字母、数字、点、下划线或短横线，并统一大小写判重 |
| 邮箱 | 选填；填写时校验格式及唯一绑定，通知／自助找回密码前须验证归属；换邮箱不改变账号、成员编号和历史操作归属 |
| 无邮箱成员 | 可使用账号密码登录，由获授权管理员重置密码；自助邮件找回不适用 |
| 角色 | 新增和编辑成员均至少选择一个，统一支持多选；可分配角色按目标机构、客户功能上限和操作者可授予权限过滤 |
| 所属机构 | 使用机构树；创建后不通过普通成员编辑跨机构移动人员，避免改变既有业务归属 |
| 初始密码 | 创建成员时由系统生成随机密码，首次登录强制修改；管理员不自行设定弱密码 |
| 修改角色 | 不能增减操作者无权分配的角色；已有更高权限角色保持只读，由有权管理员维护；不得移除最后一名有效管理员的必要管理权限 |
| 启停与删除 | 支持查询、编辑、启停、重置密码和受限删除；账号停用、管理员重置密码应使现有登录会话失效 |

本期以账号登录，不增加邮箱登录别名。若未来支持邮箱登录，仍保留内部稳定成员编号和独立账号字段，并须先完成邮箱验证及唯一性设计。

### 6.4 角色与权限管理

权限目录由系统统一维护，包含全部已交付业务菜单及相应操作；角色从目录中选择权限，不允许用户自建任意接口权限或填写权限编码。

有效权限同时受以下条件限制：**所属客户已开通功能、成员角色授权、当前操作的数据范围与业务归属规则。** 平台／客户账户边界不作为独立条件，而是权限目录中每个权限项的平台专属标注，与已开通功能一并参与过滤。多角色的菜单权限可合并；具体动作的数据范围须与授予该动作的角色一起计算，不能借其他角色的数据范围越权。

| 功能 | 内容与规则 |
| --- | --- |
| 角色维护 | 新增、编辑、复制、查询、启停、受限删除；维护名称、说明、归属机构、可管理范围和权限项 |
| 两列含义 | 归属机构＝创建并维护该角色的机构，只有该机构可以编辑；可管理范围＝持有该角色的成员能访问哪些机构的数据。取值以成员所在机构为基准，显示为“仅成员所属机构”或“成员所属机构及下级”，不使用“本机构”这类看不出基准是谁的表述 |
| 完整权限目录 | 角色页面覆盖所属账户边界内的设备、分组、升级内容、任务、激活记录、证书、系统管理、日志与会话等所有已开通模块，取消原先仅展示几个模块的简化表单 |
| 页面是否一致 | 使用相同组件和权限目录，但显示内容及可勾选项因账户边界、客户开通范围、操作者可授予权限而不同；不以“角色名称”硬编码几个固定页面 |
| 平台角色 | 只配置平台账户边界内权限；平台客户功能授权与平台人员自己能否操作客户支付密钥分开控制 |
| 客户／机构角色 | 只显示客户已开通功能；平台专属模块直接隐藏；客户范围内但当前操作者无权授予的操作显示灰色不可选 |
| 操作细分 | 按业务定义，不机械地每页都有增删改。例如 OTA 有发布／停止，成员有重置密码，授权码有撤销，日志只有查看／导出，在线会话有强制下线 |
| 权限配置形态 | 按菜单分组平铺展示，每行一个菜单，行内是该菜单可配置的操作复选框，不可授权项置灰。不采用可折叠树：配权限是自上而下逐项过一遍的任务，折叠会隐藏已勾选状态，父节点半选态也存在歧义 |
| 查看依赖 | 勾选业务操作时自动勾选该模块查看；取消查看同步取消可编辑的操作权限；保存时再次校验依赖 |
| 防止越权授权 | 只能新增、移除当前有权授予的权限；已有但无权维护的权限保留只读。复制上级角色时只带入当前可授予部分 |
| 内置角色 | 默认提供平台管理员、客户管理员、机构管理员三类模板，保护必要管理能力，不提供编辑、启停和删除；列表中角色名旁标注“内置”，让不可操作的原因可见。需要差异化权限时复制为自定义角色 |
| 只读角色 | 按需创建自定义角色，仅授予指定模块查看权限；不预置独立监控身份和专属首页，不因角色精简而增加成员权限 |
| 可管理范围 | 提供“仅成员所属机构”“成员所属机构及下级机构”，默认后者；只能在自身可授予范围内配置 |
| 权限变更 | 提示受影响成员，保存后后续请求按新权限校验；角色变更不能只更新菜单而不更新接口鉴权 |
| 新增系统功能 | 新权限纳入统一目录，但不自动授予已有普通角色；由有权限的管理员按需授权 |

### 6.5 产品与型号管理

- 平台维护产品类别、产品名称、图片、描述及型号。
- 产品类别仅保留“传统POS”“台式POS”，移除“其他／其它”选项；新增类别在实际产品需求明确后调整。
- 一个产品可包含多个型号，型号标识在平台内唯一。
- 支持新增、编辑、详情、查询及受限删除；已被设备、客户或升级内容引用的型号不能移除。
- 型号用于客户授权、设备入库、内容适配和任务设备筛选。

### 6.6 操作日志

**以可识别的业务操作作为主记录单位，不直接把每次接口调用都作为操作日志。** 接口访问日志另行记录请求方法、路径、响应码和耗时，用关联编号连接业务审计记录。设备侧的接口访问情况在设备详情“通信记录”中按设备呈现（见 3.1），与后台人员操作日志分开，两者通过同一关联编号串联。

| 维度 | 设计规则 |
| --- | --- |
| 业务模块 | 使用稳定模块编码，如客户管理、机构管理、成员管理、OTA任务、升级包管理、在线会话；通常与一级功能菜单对应，但不按每个弹窗、页签或接口单独建模块。菜单改名不改变历史归类 |
| 操作类型 | 新增、编辑、删除、导入、导出、发布、停止、启停、功能授权、角色分配、重置密码、强制下线等独立字段 |
| 业务对象 | 保存对象类型、编号及当时名称，如任务编号、成员编号、设备流转批次；对象改名后历史操作仍可解释 |
| 操作主体 | 账号、昵称、所属客户／机构、操作时间、来源 IP；不能只依赖会变化的显示名称 |
| 操作结果 | 记录服务端实际业务成功、失败或部分成功，以及必要失败原因；拒绝授权等安全事件保留记录 |
| 修改内容 | 记录必要字段的变更前后摘要，例如客户菜单授权变化、角色权限变化、目标机构变化；敏感字段采用白名单和脱敏规则 |
| 批量业务 | 批量出库／转移记录一条操作摘要，关联批次号及逐台业务明细，避免把每台设备都平铺成一条主操作日志 |
| 多接口流程 | 上传、校验、保存可能涉及多个接口；围绕业务提交结果记录可追踪事件，使用关联编号定位各接口请求，不按按钮点击次数计数 |
| 异步任务 | “发布 OTA 任务成功”仅代表任务成功发布；每台设备升级结果进入 OTA 执行记录，不把发布成功解释为设备执行成功 |
| 查询与导出 | 普通列表翻页、筛选不逐次进入业务操作日志；敏感详情访问、数据导出、权限和密钥相关操作按审计要求记录 |
| 敏感信息 | 不记录密码、完整授权码、会话令牌、私钥、支付密钥明文或上传文件原文；接口参数也不能不加筛选地全部落库 |
| 页面功能 | 按业务模块、操作类型、人员、对象、时间和结果查询，查看详情及变更摘要，按授权范围导出；不提供普通用户修改／删除日志入口 |

### 6.7 登录日志与在线会话

两者分开：登录日志回答“历史上谁何时登录过”，在线会话回答“当前哪些登录仍有效”。

| 页面 | 功能与规则 |
| --- | --- |
| 登录日志 | 查询账号、机构、登录时间、成功／失败、失败原因、IP、浏览器／系统；只读保留历史，不提供任何操作入口 |
| 两者不互联 | 登录日志不提供跳转在线会话的入口，也不增加“是否仍在线”列。登录记录与会话之间没有可靠关联，按账号跳转指向的是该账号的全部会话而非这一条登录；需要处置时直接进在线会话菜单，按账号或 IP 查询即可 |
| 在线会话列表 | 每行对应一个登录会话，展示账号、姓名、机构、后台／工具入口、IP、浏览器／客户端、登录时间、最近活动时间；同一账号可有多条 |
| 强制下线 | 单独授予操作权限，仅处理管理范围内的有效会话；填写原因并二次确认，一次只结束一条会话。不提供“结束该账号全部会话”：该动作是账号级的，放在会话行上会在同账号多条会话时重复出现，且其场景已由成员管理的停用账号与重置密码覆盖，两者更彻底——会话失效的同时禁止继续登录 |
| 当前会话 | 在账号列以标签标注“当前会话”，操作列显示占位符；不提供强制下线自身的按钮，退出请使用正常退出入口 |
| 下线效果 | 后端使会话及对应续期能力失效，后续请求要求重新登录；仅刷新前端页面、删除客户端缓存或隐藏菜单不算完成强制下线 |
| 账号状态 | 强制下线不等于停用，账号仍可重新登录；需要禁止继续登录时另行停用账号 |
| 业务影响 | 人员下线不改变设备归属，不停止已发布 OTA／RKI／模式任务；工具登录会话失效限制新的受保护请求，已开始设备流程按业务会话规则处理 |
| 自动失效 | 账号停用、管理员重置密码、组织停用等事件使相关人员登录会话失效，记录原因；不将授权码、激活会话和后台登录会话混为同一种对象 |
| 审计记录 | 强制下线记录操作者、目标账号／会话记录编号、原因、时间及结果；列表中的会话编号不是可用于认证的原始令牌 |

HTML 展示本地页面交互、权限配置及会话状态变化；真实邮件发送、邮箱验证、接口鉴权、登录令牌撤销和服务端审计在后端阶段实现。

## 7. 跨模块统一规则

| 规则 | 确认内容 |
| --- | --- |
| 租户隔离 | 客户只能访问自身授权范围内的数据；平台可按平台业务职责跨客户查看。平台可开通密钥与 RKI 菜单，但不因此自动获得客户支付密钥操作权限——这些菜单不进入内置角色，需自定义角色显式授予 |
| 客户功能上限 | 平台为客户开通可用模块，客户角色只能在该范围内分配菜单及操作；开通模块不自动授予所有成员权限 |
| 数据范围与操作分离 | 看得到数据不等于可以维护；操作必须同时满足对应动作权限、该动作的数据范围及业务归属规则，多角色不能拼接权限绕过限制 |
| 任务维护归属 | **只有任务创建机构内具有相应权限的成员可以维护任务**，不是仅限创建人本人 |
| 上级查看子级任务 | 上级在数据权限允许时可查看子级任务和进度，但不能修改目标范围、发布、停止或删除子级任务 |
| 子级查看上级任务 | 上级任务涉及子级设备时，子级仅查看本机构授权范围内的设备执行结果，不取得整项任务维护权限 |
| 模式设置权限 | 仅平台账户在角色授权范围内创建和维护模式任务；客户与下级机构不提供模式设置入口，后端同样执行权限校验 |
| 报废与归属 | 报废保留原客户／机构，退出可用设备范围；退货回收才会把设备归属调整到平台，两者分开处理 |
| 父级选择设备 | 设备转移至子级后，父级在“本机构及下级机构”范围内仍可查看并选择这些设备创建自己的任务 |
| 任务状态 | OTA、RKI、设备模式任务统一使用草稿、执行中、已完成、已停止。“发布”是操作，不再单列“已发布”状态；发布成功立即进入执行中，表示任务已生效并等待或正在由设备执行，不代表所有设备已开始。OTA仍按有效期与版本条件匹配，未到开始时间的设备不会提前执行 |
| 任务统计 | 顶部保留任务总数、执行中、草稿三项，均按当前用户可见范围统计。移除“下级及上级任务”统计卡；该指标只反映来源，且原型通过不可维护任务数量估算，不能准确代表上下级关系。列表继续显示所属机构、任务关系和维护权限，跨机构查看规则不变 |
| 发布后维护 | 已发布任务不直接修改内容、目标版本／模式和目标设备范围；需要变更时通过新任务处理 |
| 任务停止 | 填写停止原因，停止安排新的执行；已开始的设备可能继续完成，已完成结果不回滚 |
| 任务冲突 | 发布前校验同设备相关业务的待执行任务冲突，避免同一目标收到相互冲突的安排 |
| 组织停用 | 停用客户或机构限制本组织及下级人员访问，不自动停止已发布任务、不自动锁定设备；恢复后不自动恢复被单独停用的成员 |
| 历史保留 | 设备报废、退货回收、归属转移和任务停止均保留必要历史记录；被业务引用的数据限制物理删除 |

## 9. 本阶段边界与后续细化事项

- 本期不交付 8583 报文解析、签到、消费等认证测试能力。依据《POS APP 对接 TMS 功能需求》A1：只有 UPTS 认证需要这些功能，PCI 认证不需要。是否补做取决于是否申请 UPTS 证书。
- 不支持 RKI 的客户，终端主密钥通过母 POS 经串口本地导入（母 POS 作主设备，密钥密文由 KEK 保护）。该通道不经过 TMS 网络，不在本系统范围内。
- 本期不接硬件加密机，CA 与证书全部由软件实现：三类 CA（激活、RKI、TLS）由平台自签生成，设备证书与平台服务证书由对应 CA 签发。CA 私钥加密保存在证书服务内并在线可用，以支撑激活和 RKI 流程中的签名。硬件加密机部署、安全房和相关管控不纳入当前范围，但签名与签发动作统一走密码服务接口，便于后续替换实现。
- 当前证书页面不纳入吊销、CRL 发布；是否补充这部分生命周期能力，后续结合证书使用方式确认。
- 设备交互协议、报文格式、密钥封装、重试和超时规则在后端服务设计中确定，不在页面阶段定死。
- 已发布任务按发布时设备名单展示和管理；永久任务是否需要自动纳入后续新增设备，在任务匹配机制设计时进一步细化，不默认扩大目标范围。
- 客户自有 OTA／RKI 服务的对接方式需结合具体客户确定，当前不增加未定义的第三方服务配置页面。
- 本期不做设备端上报日志（设备应用日志、崩溃日志）。设备交互协议中尚无日志上报通道，需固件配合；此类日志为 MB 级文件，集中存储成本与 POS 交易相关内容的合规边界均需另行确认。后续若补充，形态定为「日志提取任务 + 日志文件列表（下载与留存期）」，与 OTA、RKI、模式任务并列为一种设备任务，而非设备详情内的常驻日志栏。
- 设备报文记录按日分区保留 30 天；“不需要更新”的更新请求每台设备只保留最近一条。实际写入量在联调阶段按设备轮询周期复核。
- 本期不做机构与成员的邮件邀请，统一走直接创建加系统随机密码加首登强制改密。原因是邮箱为选填、覆盖不到没有企业邮箱的工厂人员，邀请只能作为第二套并行开户流程存在；且邮件服务在私有化部署下是额外的对接点与故障点。若客户明确要求初始密码不经管理员之手，后续用一次性开户码替代（管理员通过任意渠道转交，对方自行设置密码），不绑定邮箱、不依赖邮件服务。
- 当前页面只制作中文版本，保留语言入口；国际化翻译与英文页面不纳入本次交付。

## 10. 本轮设计依据

- 《服务器说明_20240629.docx》：OTA 区分内容、型号与版本；激活要求工具账号登录、SN 合法性校验和设备结果确认；CA 服务承担证书生成、分发与验证；RKI 涉及设备与服务端身份材料。原文未明确授权码次数、有效期长度、CA固定层级以及所有证书的签发时机。
- [OWASP Transaction Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Transaction_Authorization_Cheat_Sheet.html)：建议将登录认证与业务授权区分，授权凭证应绑定每次操作、在有限时间内有效并防止重放。本项目“一码一机一次会话”据此设计，10分钟为建议默认值。
- [RFC 5280](https://www.rfc-editor.org/rfc/rfc5280.html)：X.509 证书、信任锚与证书路径验证依据；未规定所有系统必须固定两层或三层。本项目三层 CA 为架构建议。
- [RFC 7030](https://www.rfc-editor.org/rfc/rfc7030.html)：提供证书注册、重新注册和密钥持有证明等机制，可作为设备证书申请设计参考；不表示本期已经确定采用 EST 协议。

支付 RKI 的密钥管理要求须结合实际产品、客户信任体系和适用认证范围进一步确认；本轮通用证书设计不等同于支付行业认证结论。
