# 通讯接口定义
## 接口列表

| 序号 | 接口名称 | 内容 |
| --- | --- | --- |
| 1 | 激活握手接口 | 激活握手请求：上送传输密钥+随机数B握手响应： 下发随机数A |
| 2 | 激活接口 | 申请激活：上送自毁原因+申请下发的RSA密钥类型激活响应： 下发终端模式+激活标志+RSA密钥 |
| 3 | 认证接口 | 认证请求:上送随机数A认证响应：下发随机数B。 |
| 4 | 密钥下载接口 | 密钥下载请求：请求密钥下载密钥下载响应：下发终端模式+密钥 |

注意：当终端收到的后台下发的终端状态与原来的不一致时，需要更新终端状态。
终端状态：是指当前终端是处于何种模式，比如debug、product、Lock、factory等。
## 激活握手接口
### 请求报文

| 字段名称 | 字段含义 | 字段类型 | 字段长度 | 字段说明 |
| --- | --- | --- | --- | --- |
| msgLength | 报文长度 | HEX | 2 | 必填 |
| orderCode | 命令码 | String | 2 | 必填 |
| AuthorCode | 授权码 | HEX | 16 | 必填,不足右补0x00 |
| SNLength | SN长度 | HEX | 1 | 必填 |
| SN | POS序列号 | AN | Var | 最大32字节 |
| TransKey_RSA | 传输密钥密文 | HEX | 256 | 不足，左补0x00 |
| lrc | 校验位 | Byte | 1 | 必填 |

AuthorCode:
由认证工具点击”授权码”按钮向服务器申请，服务器认证用户权限后，直接发送到申请人的邮箱。授权码有使用次数和使用时间。
TransKey_RSA:
终端随机生成32字节的随机数，作为AES传输密钥TransKey
生成传输密钥的CV值：传输密钥对16个0x00加密，取前4字节
生成16字节随机数A
组包数据M1=TransKey+CV+A
组包数据M2=SNLen+SN+0x00 到长度与M1相同
组包数据：M=M1 xor M2
用CA_PK，对数据M进行PKCS1加密。
备注:终端启动后，如果在10分钟内，无法完成激活或者失败，即销毁密钥并结束通讯。
### 响应报文

| 字段名称 | 字段含义 | 字段类型 | 字段长度 | 字段说明 |
| --- | --- | --- | --- | --- |
| msgLength | 报文长度 | HEX | 2 | 必填 |
| orderCode | 命令码 | String | 2 | 必填 |
| responseCode | 响应码 | String | 2 | 必填 |
| Data_Cipher | 密文数据 | HEX | 16 | 不足，左边补0 |
| Sign | 签名 | HEX | 256 | 不足，左边补0x00 |
| lrc | 校验位 | Byte | 1 | 必填 |

CipherData:
服务器生成16字节随机数B.
M= 随机数A xor 随机数B
用密钥K 对M进行AES加密。
Sign:
获取数据M1=SNLen+SN+ RandomA+RandomB
对数据进行SHA256计算，获取HASH值M
用CA_SK 对M进行PKCS1加密。
备注：服务器在下发数据后，如果5分钟内没有收到激活请求，则断开连接，清除所有保存的握手数据。
## 激活接口
### 激活报文

| 字段名称 | 字段含义 | 字段类型 | 字段长度 | 字段说明 |
| --- | --- | --- | --- | --- |
| msgLength | 报文长度 | HEX | 2 | 必填 |
| responseCode | 命令码 | String | 2 | 必填 |
| AuthorCode | 授权码 | HEX | 16 | 必填,不足右补0x00 |
| SNLen | SN 长度 | HEX | 1 | 必填 |
| Sn | Pos序列号 | AN | 32 | 最大32字节 |
| TermStatus | 终端状态 | HEX | 4 | 终端状态 |
| ActiveReqData | 激活请求数据 | HEX | 16 | 必填 |
| lrc | 校验位 | Byte | 1 | 必填 |

ActiveReqData:
组包数据M1=SNLen+SN+RandomB
M2=M1后补0x00到16字节对齐，然后16字节异或
M3=终端状态（4字节）+终端自毁原因（4字节）+密钥标志(4)+随机数(4)
M = M2 xor M3
用TransKey 对M进行AES加密
密钥标志：密钥标志(4字节)+Term_SK(私钥,密钥标志bit0=1时存在)+Term_PK(公钥,密钥标志bit1=1时存在) ，位组组合4字节，如，成无加密[0,0,0,0]，私钥公钥加密[0,0,0,3]
### 响应报文

| 字段名称 | 字段含义 | 字段类型 | 字段长度 | 字段说明 |
| --- | --- | --- | --- | --- |
| msgLength | 报文长度 | HEX | 2 | 必填 |
| orderCode | 命令码 | String | 2 | 必填 |
| orderCode | 响应码 | String | 2 | 必填 |
| ActiveRespDataLength | 激活应答数据长度 | HEX | 2 | 必填 |
| AcitveRespData | 激活应答数据 | HEX | Var | 不够，左补0 |
| Sign | 签名 | HEX | 256 |  |
| lrc | 校验位 | Byte | 1 | 必填 |

ActiveRespData:
组包数据M1=SNLen+SN+RandomA
M2=M1后补0x00到16字节对齐，然后16字节异或
M3=终端状态（4字节）+激活结果（4字节）+密钥标志(4)+Term_SK(var,密钥标志bit0=1时存在)+Term_PK(var,密钥标志bit1=1时，存在)+0x00，到16字节对齐
M = M2 xor M3
用TransKey 对M进行AES加密
Sign:
组包M1 = SNLen+Sn+RandomA+终端状态(4)+激活结果(4)+ 密钥标志(4)+Term_SK(var)+Term_PK(var)
M= SHA256(M1)
用CA_SK 对M进行PKCS1加密。

## 认证接口
### 请求报文

| 字段名称 | 字段含义 | 字段类型 | 字段长度 | 字段说明 |
| --- | --- | --- | --- | --- |
| msgLength | 报文长度 | HEX | 2 | 必填 |
| orderCode | 命令码 | String | 2 | 必填 |
| AuthorCode | 授权码 | HEX | 16 | 不足，右边补0x00 |
| SNLength | SN长度 | HEX | 1 |  |
| posSN | 序列号 | HEX | Var | 最大32 |
| AuthorType | 认证类型 | HEX | 1 | 0 CA认证 1 RKI认证 |
| ReqCipherData | 密文数据 | HEX | 256 | 不足，左边补0x00 |
| PKLen | 公钥长度 | HEX | 2 | 长度为0，表示不上送公钥，后台根据终端SN从数据库读取 |
| PK | 公钥 | HEX | Var | 不足，右边补空格 |
| Sign | 签名 | HEX | 256 | 不足，左边补0 |
| Lrc | 校验位 | Byte | 1 | 必填 |

ReqCipherData:
M= KeyType（4）+终端生成的32字节随机数A+随机数T(8)+单包最大长度(4)
用CA_PK或者RKI_CA_PK 对M进行PKCS1加密。
Sign:
M1 = SNLen+SN+认证类型+CipherData+PKLen+PK
M = SHA256(M1)
用Term_SK 或者Term_RKI_SK对M进行PKCS1加密。
KeyType:
bit0:  Term_TLS_SK,
bit1：Term_TLS_PK
bit2：Term_RKI_SK,
bit3：Term_RKI_PK
bit7：0：TR31方式下发RSA密钥，1，表示直接下发RSA密钥
bit8： DUKPT
bit9： MSK_MK
bit10: MSK_PINK
bit11: MSK_MACK
bit12: MSK_DATAK
bit16: Fixed_PINK
bit17: Fixed_MACK
bit18: Fixed_DataK
认证类型：0表示终端CA认证， 1表示RKI认证，
注:  RKI认证时，授权码固定为0x00.
CA 认证时，授权码为后台下发。
### 响应报文

| 字段名称 | 字段含义 | 字段类型 | 字段长度 | 字段说明 |
| --- | --- | --- | --- | --- |
| msgLength | 报文长度 | HEX | 2 | 必填 |
| orderCode | 命令码 | String | 2 | 必填 |
| responseCode | 响应码 | String | 2 | 必填 |
| ResCipherData | 响应密文 | HEX | 256 | 不足，左补0x00 |
| PKlength | 服务器公钥长度 | HEX | 2 | 长度为0，表示服务器不下发公钥，终端使用默认的CA公钥 |
| PK | 服务器公钥 | HEX | Var |  |
| Sign | 签名 | HEX | 256 | 不足，左补0x00 |
| lrc | 校验位 | Byte | 1 | 必填 |

ResCipherData:
M=KeyType(4)+后台生成的32字节随机数B+32字节的KBPK+密钥总个数(2)+随机数R(8)
用Term_ PK或者Term_RKI_PK 对M进行PKCS1加密。
Sign:
M1 = SNLen+SN+ CipherData+PKlength+PK
M = SHA256(M1)
用CA_SK或者RKI_CA_SK 对M进行PKCS1加密。
注：终端和平台完成认证后，双方将获得传输密钥TransKey = RandomA xor RandomB, 后续的数据加密将用TransKey进行AES加密。密钥生成后，如果10分钟内，没有完成下载，则销毁密钥。同时，终端将获得KBPK，此密钥为AES256，该密钥将用于密钥加密和mac计算。
加密密钥和mac密钥的生成方式，采用CMAC方式。
注2：终端判断后台下发的keytype与终端上送的是否一致，如果不一致，则判断是否继续请求下载或者报错（必须下载的密钥不存在时，必须报错）
## 密钥下载
### 请求报文

| 字段名称 | 字段含义 | 字段类型 | 字段长度 | 字段说明 |
| --- | --- | --- | --- | --- |
| msgLength | 报文长度 | HEX | 2 | 必填 |
| orderCode | 命令码 | String | 2 | 必填 |
| AuthorCode | 授权码 | HEX | 16 | 不足，右边补0x00 |
| SNLength | SN长度 | HEX | 1 |  |
| posSN | POS序列号 | AN | Var | 最大32字节 |
| TermStatus | 终端状态 | HEX | 4 | 不足，右边不空格 |
| ReqEncData | 请求的密文 | HEX | 16 | 必填 |
| lrc | 校验位 | Byte | 1 | 必填 |

ReqEncData:
M =终端状态(4)+密钥索引(2)+NextPack(1)+上一包的KCV(4)+ 随机数R(8)+随机数（13）
用TranskKey 对M 进行AES加密
如果是第一次请求，则KCV=0x00000000，如果服务器判断当前请求的密钥之前的密钥的KCV未收到，则从未收到KCV的密钥索引开始下发。比如，终端请求密钥索引为8，但是，服务器发现未收到过密钥索引4的KCV，则服务器从密钥索引4开始下发。
如果下发的是非对称密钥，则KCV = 全0，表示成功，其他表示失败。
### 响应报文

| 字段名称 | 字段含义 | 字段类型 | 字段长度 | 字段说明 |
| --- | --- | --- | --- | --- |
| msgLength | 报文长度 | String | 2 | 必填 |
| orderCode | 命令码 | String | 2 | 必填 |
| responseCode | 响应码 | String | 2 | 必填 |
| NextPack | 下一包 | HEX | 1 | 0：表示最后一包，1表示还有下一包。用于密文数据超过单包总长度 |
| respEncDataLength | 密文数据长度 | HEX | 2 | 必填 |
| RespEncData | 密文数据 | HEX | Var |  |
| Lrc | 校验位 | Byte | 1 | 必填 |

RespEncData：
M =密钥总个数(2)+密钥当前索引 (2)+随机数T(8)+密文格式(1)+密文数据 +补齐到16的倍数
用Transkey 对M进行AES加密。
密文格式：0x00表示 TR31 , 0x01 表示直接下载
TR31的数据格式为：
KBH(16)+KBH(Option, var multiply to 16bytes)+KeyCipherData(var)+MAC(16*2=32)
MAC= BCDtoAsc(CMAC(KBMK, KBH+KBH(Option)+KeyLen+KeyData+padding))
KeyCipherData：BCDtoAsc(Enc(KBEK, M))
M = Keylen(2byte,以bit为单位,hex格式)+keyData+random(padding to 16 字节倍数)
如果下载的是对称密钥(DUKPT,MSK,FixedKey等)，则M=定长48字节。
如果是非对称密钥，则补齐到16字节的倍数
RSA密钥直接下载的数据格式为：
RSA 证书密文：= enc(KBEK,M)
M = 密钥体系(1)+密钥算法(1)+密钥索引(1)+keylen (2,字节单位)+keydata+KSNLen+KSN+random(pandding to 16字节倍数)
其中，KSNlen+KSN字段只有密钥体系为DUKPT时存在。
如果已经是最后一包，则密文数据体不存在，且总个数=当前索引

# 报文格式及校验位
## 报文格式
报文格式：长度+命令吗+报文信息+lrc
## 校验位
校验位是校验的命令吗+报文信息
